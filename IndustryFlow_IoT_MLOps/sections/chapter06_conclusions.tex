\chapter{ВИСНОВКИ}

У рамках дипломної роботи було розроблено платформу IoT MLOps для моніторингу промислових сенсорів у реальному часі з виявленням аномалій на основі машинного навчання. Проблема, яку було поставлено на початку роботи, полягала у відсутності доступних комплексних рішень для малих та середніх промислових підприємств, що поєднують потокову обробку даних, мультитенантну архітектуру та інтегровану MLOps інфраструктуру на базі технологій з відкритим кодом. Для розв'язання цієї проблеми було спроектовано та реалізовано п'ятишарову мікросервісну архітектуру, що включає шар прийому даних, шар потокової обробки (Apache Kafka та Apache Spark), шар зберігання (TimescaleDB з колонковим стисненням), шар MLOps (MLflow та MinIO) та прикладний шар (FastAPI мікросервіси та React веб-інтерфейс).

Усі заплановані функціональні вимоги було успішно реалізовано:

\begin{itemize}
    \item потокова обробка даних з пропускною здатністю 552 повідомлень/с після оптимізації;
    \item мультитенантна ізоляція на рівні схем бази даних з повною безпекою даних;
    \item стиснення TimescaleDB з коефіцієнтом 99.98\%, що забезпечує економію 342.94 GB/рік на 10 тенантів;
    \item MLOps конвеєр з відстеженням експериментів, версіонуванням моделей та реєстром артефактів;
    \item детекція аномалій з AUC-ROC 0.8887 (XGBoost) на бенчмарковому наборі даних TEP;
    \item система сповіщень з підтримкою порогових правил та ML-детекції;
    \item веб-інтерфейс з візуалізацією даних у реальному часі через WebSocket.
\end{itemize}

Кількісні результати тестування підтвердили відповідність системи поставленим вимогам --- швидкість обробки Spark досягла 1,859 рядків/с при 12 партиціях Kafka, затримка запитів до бази даних становить 10--15 мс.

До сильних сторін проєкту належать:

\begin{itemize}
    \item архітектура схема-на-тенанта, що забезпечує ізоляцію даних на рівні бази даних та дозволяє використовувати колонкове стиснення TimescaleDB;
    \item модульність мікросервісної архітектури, що дозволяє незалежно масштабувати компоненти системи;
    \item інтеграція MLflow, що забезпечує повний життєвий цикл ML моделей від експериментування до розгортання у виробництві.
\end{itemize}

До слабких сторін належать:

\begin{itemize}
    \item однонодове розгортання, що обмежує максимальну пропускну здатність системи;
    \item ручне масштабування компонентів, що потребує експертних знань;
    \item стиснення TimescaleDB, що додає +15\% затримки для запитів до великих стиснутих фрагментів;
    \item модель XGBoost, навчена на збалансованому наборі даних TEP, що може не відповідати реальному розподілу класів у промислових даних.
\end{itemize}

Платформа призначена для малих та середніх промислових підприємств, що потребують моніторингу обладнання в реальному часі, раннього виявлення несправностей для переходу до превентивного обслуговування, мультитенантного рішення для обслуговування декількох виробничих майданчиків та контролю над власними даними без залежності від хмарних провайдерів. Використання технологій з відкритим кодом усуває ліцензійні витрати та дозволяє адаптувати систему під специфічні потреби підприємства.

На основі виявлених обмежень визначено пріоритетні напрямки вдосконалення платформи:

\begin{itemize}
    \item перехід від Docker Compose до Kubernetes для автоматичного масштабування та самовідновлення сервісів;
    \item впровадження LSTM та Autoencoder для детекції складних часових патернів;
    \item реалізація детекції дрейфу даних та автоматичного перенавчання моделей;
    \item інтеграція з промисловими протоколами OPC-UA та Modbus;
    \item розробка легковісних агентів для попередньої обробки даних на межовому обладнанні.
\end{itemize}

Результати роботи підтверджують, що технології з відкритим кодом дозволяють створити конкурентоспроможну альтернативу комерційним IoT платформам для промислового моніторингу. Досягнуті показники (552 повід./с пропускної здатності, 99.98\% стиснення, AUC-ROC 0.8887) відповідають вимогам типових промислових сценаріїв та можуть бути масштабовані для більших навантажень шляхом кластерного розгортання. Внесок роботи полягає у демонстрації архітектурного підходу, що поєднує ізоляцію даних на рівні схем з колонковим стисненням TimescaleDB, та у створенні відтворюваного рішення для промислового IoT моніторингу на базі технологій з відкритим кодом.
