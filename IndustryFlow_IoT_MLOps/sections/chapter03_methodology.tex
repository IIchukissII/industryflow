\section{Методи дослідження}

У роботі застосовано комплекс методів:

\begin{itemize}
    \item аналітичний метод --- для систематичного аналізу існуючих IoT платформ та формулювання вимог до архітектури;
    \item метод моделювання --- для проєктування багаторівневої архітектури платформи;
    \item методи машинного навчання (Isolation Forest, Random Forest, XGBoost) --- для детекції аномалій у сенсорних даних;
    \item експериментальний метод --- для тестування продуктивності та ефективності стиснення;
    \item порівняльний метод --- для оцінки алгоритмів та архітектурних рішень.
\end{itemize}

Відтворюваність досліджень забезпечено через інфраструктуру як код (docker-compose.yml), фіксацію версій залежностей та збереження моделей у MLflow.


\section{Підхід до розробки}

Розробка платформи здійснювалася за ітеративною моделлю з елементами Agile. Процес складався з наступних етапів:

\begin{itemize}
    \item аналіз вимог та проєктування архітектури;
    \item реалізація базової інфраструктури (Docker, Kafka, TimescaleDB);
    \item розробка шару прийому даних та потокової обробки;
    \item інтеграція MLOps інфраструктури (MLflow, MinIO);
    \item розробка API та веб-інтерфейсу;
    \item тестування продуктивності та оптимізація.
\end{itemize}

Контроль версій здійснювався через Git з окремими гілками для кожної функціональності. Відтворюваність забезпечено через інфраструктуру як код (docker-compose.yml) та фіксацію версій залежностей.

\section{Стратегії тестування}

Для верифікації системи застосовано комплекс методів тестування:

\begin{itemize}
    \item тестування продуктивності --- вимірювання пропускної здатності та затримки при різних конфігураціях (партиції Kafka, воркери Spark);
    \item тестування безпеки --- верифікація ізоляції тенантів через спроби SQL-ін'єкцій та міжтенантного доступу;
    \item тестування ML моделей --- порівняння алгоритмів на бенчмарковому наборі даних Tennessee Eastman Process (500,000 зразків, 52 сенсори);
    \item навантажувальне тестування --- інкрементальне масштабування для ідентифікації вузьких місць.
\end{itemize}

Метрики оцінки ML моделей: точність (accuracy), влучність (precision), повнота (recall), F1-оцінка та AUC-ROC. Гіперпараметри оптимізовано через Optuna.

\section{Обмеження методології}

Методологія має наступні обмеження:

\begin{itemize}
    \item тестування проводилося на однонодовому розгортанні --- результати можуть відрізнятися при кластерному розгортанні;
    \item ML моделі навчено на збалансованому наборі даних TEP --- реальні промислові дані можуть мати інший розподіл класів;
    \item веб-інтерфейс має базову функціональність --- розширене юзабіліті-тестування не проводилося;
    \item глибоке навчання (LSTM, Autoencoder) залишено на майбутнє.
\end{itemize}

Обрані методи дозволяють досягти поставлених цілей та забезпечують відтворюваність результатів через інфраструктуру як код та версіонування моделей у MLflow.


\section{Висновки до розділу}

У розділі описано методологію розробки платформи IoT MLOps для промислового моніторингу. Застосовано комплекс методів: аналітичний для формулювання вимог, моделювання для проєктування архітектури, методи машинного навчання для детекції аномалій, експериментальний для тестування продуктивності та порівняльний для оцінки рішень.

Обрано п'ятишарову мікросервісну архітектуру з технологіями Apache Kafka та Spark для потокової обробки, TimescaleDB для зберігання часових рядів, MLflow та MinIO для MLOps інфраструктури, FastAPI для REST API та React для веб-інтерфейсу. Архітектура схема-на-тенанта забезпечує ізоляцію даних та сумісність з колонковим стисненням TimescaleDB.

Система розгорнута як 23 контейнери Docker з конфігурацією через змінні середовища, що забезпечує відтворюваність та спрощує масштабування. Стратегії тестування включають перевірку продуктивності, безпеки, якості ML моделей та навантажувальне тестування.
